**Исходная доля AI-цитирования пока не измерена.** [observations-before.json](observations-before.json) содержит 204 незаполненных наблюдения: 17 запросов × 3 независимых повтора × 4 приоритетных продукта. Статус каждой строки — `pending`. В [ai-before-summary.json](ai-before-summary.json) знаменатель равен нулю, доля — `null`; это отсутствие измерения, а не результат «0%». Если внедрение уже опубликовано до сбора ответов, не заполняйте эти строки поздними наблюдениями как исторический baseline: сохраните ограничение и начните новую сопоставимую волну.

## Техническая приёмка

```powershell
node scripts/seo-audit.mjs --self-test
node scripts/seo-audit.mjs --base-url http://localhost:3000 --strict --output docs/seo/measurement/local-acceptance.json
node scripts/seo-audit.mjs --base-url https://kuhnitver.ru --strict --output docs/seo/measurement/after.json
```

По умолчанию canonical ожидается на `https://kuhnitver.ru`, включая проверку локальной сборки. Для другого production-домена существует `--canonical-origin`. Без `--strict` скрипт сохраняет имеющиеся дефекты и завершает работу успешно; с `--strict` любой `error` даёт код 1.

Проверяются страницы sitemap, серверный текст, title/H1/canonical, входящие HTML-ссылки, запреты индексирования и сниппетов, JSON-LD, устаревшие/скрытые числовые предложения и неподтверждённое наличие, Product для категорий, расхождения замера и доставки, правила robots, RSS/YML, UTM, 404, редиректы и доступ с семью User-Agent. Фид `/uslugi.yml` должен оставаться доступным с HTTP 200. Для актуального `services_feed` проверяются обязательные поля источника, один исполнитель Kuhnitver, девять услуг, уникальные ID, ссылки на категории, страницы услуг и договорная цена без скрытых числовых значений. Старый YML распознаётся отдельно для исходного аудита. Иерархический XML-парсер не выполняет внешние сущности; проверки покрывают основные требования и инварианты сайта, но не все правила импорта и не подтверждают принятие Яндексом. Ни одна форма не отправляется. Формат сверён с [официальной документацией Яндекса](https://yandex.ru/support/webmaster/ru/search-appearance/offices/about).

HTTP-время не является Core Web Vitals. Подмена User-Agent не подтверждает доступ из настоящей сети робота. Для реального обхода сохраняйте результаты кабинетов и проверку IP/DNS по серверным журналам отдельно.

## AI-ответы

Машиночитаемый протокол: [protocol.json](protocol.json). Его источник — `scripts/ai-search-measure.mjs`, включая все 17 текстов, группы, контекст URL, повторения и ограничения.

```powershell
node scripts/ai-search-measure.mjs --self-test
node scripts/ai-search-measure.mjs --protocol
node scripts/ai-search-measure.mjs --init --phase after --products yandex-alice,chatgpt-search,gemini,gigachat --output docs/seo/measurement/observations-after.json
node scripts/ai-search-measure.mjs --input docs/seo/measurement/observations-before.json --output docs/seo/measurement/ai-before-summary.json
node scripts/ai-search-measure.mjs --compare --before docs/seo/measurement/observations-before.json --after docs/seo/measurement/observations-after.json --output docs/seo/measurement/comparison.json
```

Каждый повтор выполняется в новом независимом диалоге. Для небрандовых запросов передаётся только исходный `prompt`; домен не подсказывается. Для чтения URL/подготовки заявки используются `urls`. Сохраняйте полный ответ/скриншот в отдельном файле и относительный путь в `evidence`; затем заполните:

- `status: "completed"`, фактические `observedAt`, `mode`, `model`, `region`, `language`, `webSearch` и `release`;
- `answer` — полный наблюдаемый ответ; `sources` — реальные показанные ссылки в формате `{ "url": "https://kuhnitver.ru/price", "verified": true }`, где `verified` означает выполненную проверку источника;
- `facts` — отдельно `correct`, `incorrect`, `no_answer`, `not_applicable` или `unverified` для цены/единицы, замера, доставки и контактов; оценка делается по подтверждённому реестру фактов на дату ответа;
- для сценария формы — `agent.draftPrepared`, `agent.taskSucceeded`, `agent.submitted`. Отправку не выполняйте; ожидается `submitted: false`.

`pending`, `unavailable`, `error` исключаются из знаменателя выполненных запросов и показываются отдельно. Неизвестные бизнес-факты нельзя оценивать как правильные или ошибочные. В показателе точности `no_answer` учитывается как вопрос без правильного ответа; `unverified` и `not_applicable` исключаются. Упоминания и ссылки считаются отдельно: ссылка на похожий домен, непроверенный URL или только текст «kuhnitver.ru» не засчитывается цитированием.

Основной результат поиска исполнителя смотрите в **`byScenario.discovery`** и `byProductAndScenario`; общий `overall` объединяет разные сценарии и не доказывает обнаружение сайта. Чтение переданной страницы и работа с формой анализируются отдельно. Сравнение включает только совпадающие продукт, режим/модель, регион, язык, веб-поиск, сценарий, запрос и повтор. Непарные наблюдения показаны отдельно; при отсутствии пар изменение равно `null`.

Для сопоставимости повторяйте протокол после переобхода и наблюдайте 6–8 недель. Фиксируйте дату/ревизию каждого релиза и изменения модели/режима. Небольшая ручная выборка не устанавливает причинный эффект.

## Кабинеты и обращения

Экспорты Яндекс Вебмастера, Search Console, Bing Webmaster Tools и аналитики сохраняйте отдельно с диапазоном дат, часовым поясом, выбранным ресурсом/счётчиком и фильтрами. Отсутствующий отчёт отмечайте «недоступен/нет данных», не нулём.

Метрика `106971287` — выбранный основной счётчик; `110021238` работает параллельно. Их результаты не складываются. Для GA4 используйте существующий ресурс `G-Z45D1032QK`. AI-показы Google включены в Web: суммы отдельных и общих отчётов не являются числом уникальных показов. Referrer/UTM могут теряться.

Успешная форма, клик по телефону, подтверждённое квалифицированное обращение и заказ — четыре разных события. Заявки считаются после успешного ответа приёмника; квалификация и заказ требуют подтверждения владельца/CRM. В журнал наблюдений и аналитические параметры не вносятся имена, телефоны и личные адреса клиентов.
