## Предложение для точного следующего среза — не применено

Подготовлен отдельный local-only поток `/var/log/nginx/kuhnitver-bots.log` внутри собственного HTTPS apex-vhost. Он должен сохранять фактический `$http_host`, выбранный `$server_name`, URI без args, метод/статус, время и нормализованную claimed-bot family. Source address нужен только локально для официальной IP/DNS-проверки и не попадёт в репозиторные агрегаты. Сырые UA, args, referrer, cookies и body в новый формат не включаются. Обычные браузеры в этот дополнительный поток не записываются; bot family по UA остаётся кандидатом, а не подтверждённым роботом.

Существующий combined-поток предлагается явно сохранить вторым `access_log` на том же уровне: локальные директивы переопределяют наследуемое логирование. Для нового файла нужны начальные права `0640 www-data:adm`; существующее правило `/var/log/nginx/*.log` уже покрывает daily rotation, 14 архивов, сжатие и создание с этими правами. Новый logrotate-конфиг не требуется. Другие vhost и текущая freshness-политика не меняются.

Это только предложение для review; новый лог, его конфигурация и reload не создавались. Механизмы: [nginx access_log / conditional logging / JSON escaping](https://nginx.org/en/docs/http/ngx_http_log_module.html), [nginx map](https://nginx.org/en/docs/http/ngx_http_map_module.html).
